# UXP 安装成功但 Photoshop 没有加载

适用本次 Win10／Photoshop 2024（25.5）报告：文件与凭据有效，增效工具菜单完全没有本插件，加载日志显示使用用户 PluginsInfo 索引、只登记另一个插件，未扫描用户 External 目录。

147修复已有用户索引遗漏本插件的情况。已在本机真实 PS24.0.1 复现同一条件：索引只列另一个测试插件时本插件没有加载；补齐本插件登记后，两者均成功加载，UXP0.3.18心跳恢复。Windows 的 `$localPlugins` 登记路径必须使用反斜杠，正斜杠在本机导致加载器无法初始化路径。故障电脑的 Win10／PS25.5 仍需升级后确认，不能将本机结果等同于该电脑已通过。

当前148继续保留147加载登记修复，内置／本机实际加载UXP0.3.19；读取优化与跨机未验收范围见[当前交付](../README.md)。以下147／18复现结果是当时证据。

## 使用

1. 更新主程序到147或更高版本，确认后台实际运行版本。
2. 保存并正常关闭 Photoshop，后台保持运行。默认开启的“已安装UXP自动跟随内置版本更新”会在约15秒检查中修复缺失／过期登记；旧插件同时跟随内置版本更新。
3. 跟随更新已关闭、加载登记被禁用，或希望主动修复时，进入“插件管理 → 安装与状态”，点击“修复并启用加载登记”。未安装可用插件时先安装内置插件。
4. 重新启动 PS，在后台确认实际加载版本和“Photoshop 已加载，可执行操作”。文件校验通过或登记成功都不单独代表宿主已加载。

仍未连接时，在“运行状态 → 统一诊断”选择“UXP安装与加载”并导出报告；保留 PS 开启。报告包含登记状态及本次宿主加载日志，不导出共享索引中的其他插件记录。

## 修改与回退范围

- 文件仍在当前用户 `%APPDATA%\Adobe\UXP\Plugins\External`，凭据不进入系统共享目录，不需要管理员权限、Adobe账号、Marketplace、UDT或UPIA。
- 仅当 `%APPDATA%\Adobe\UXP\PluginsInfo\v1\PS.json` 已存在时维护本插件条目。没有索引时不新建，保留原目录扫描方式，避免隐藏其他未登记插件。
- 保留其他插件条目、顺序、未知字段和索引元数据；本插件的版本／名称／路径随安装与语言应用同步。自动更新保留原有禁用状态；只有主动修复才启用加载登记。“禁用执行”是后台接收任务开关，与Adobe索引的加载状态分别处理。
- 卸载只移除本插件条目；回退只合并恢复本插件的原条目，不用整份旧索引覆盖其他插件的新改动。操作前保存私有索引恢复副本及本插件快照。
- 索引损坏、重复字段／重复本插件ID、未知结构、超过2MiB或本插件指向其他路径时停止修改，保留原文件。提交前检测索引字节变化，冲突时拒绝覆盖并恢复本次插件文件修改。
- PS运行、任务忙碌、未核对结果、启动未结束及菜单展开时，自动维护沿用原保护；手动维护还要求正常关闭PS。不会自动结束PS、清除忙碌状态或重发请求。

这是应用的本地兼容维护方案，不等同于Adobe官方安装器认证。登记结构参考[插件作者的 Windows 安装实现](https://github.com/cdmusic2019/comfyui-photoshop/blob/main/Install_Plugin/installer.py)，行为以本项目真实宿主复现与验证为依据；不承诺所有Photoshop版本均已验收。
