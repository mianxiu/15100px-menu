# 连续组合键与执行耗时

## 166／UXP33 本机验证版

已切换本机实际入口；正式 GitHub Release 仍为165。无需修改原来的 Caps+W／S 或 Shift+Caps+W／S 绑定。

用户反馈需要重复按几次才执行。旧165的实际日志中，两次组合键已被原生钩子识别，并在1–2毫秒内进入后台，但上一项选层任务仍在执行，因此被忙碌保护拒绝。成功任务约172–281毫秒。这证实了一种漏执行原因，不代表所有未响应都只有这个原因。

166先读取待执行请求，再处理可选的菜单／颜色读取；捕获目标后的原有短暂交接窗口也覆盖可选菜单读取，避免下一条写入尚未到达时启动无关读取。不改变后台刷新间隔、快照有效期、Caps按下立即展开或按键判定时间。已开始的宿主读取仍需正常返回，不能抢占。

Caps选择／样式／单步移动事务中，根级列表至少64项时复用已验证的原生标量批量读取，检查操作前后完整图层结构。较小列表沿用DOM；原生接口不支持、返回异常或原生条目超4096时回退完整DOM。全树成员校验使用集合查找。目标身份、完整数量与顺序、最终选择、锁定、写后核验和历史事务保持；深层分组但根级不足64项的文档仍使用原路径。

## 本机证据

PS24.0.1，双逻辑处理器／Below Normal；每组16项选层／追加多选事务，包含旧目标拒绝检查：

| 文档 | 165中位 | 166中位 | 166最大 |
| --- | --- | --- | --- |
| 5层，CPU受限 | 218.20ms | 221.84ms | 267.94ms |
| 100层，CPU受限 | 318.90ms | 250.19ms | 302.51ms |
| 100层，正常资源 | 未测 | 236.21ms | 277.57ms |

这是桥接事务耗时，包含捕获目标与写后结果；不是实体按键到屏幕延迟。升级期间重启过PS，不是同会话交替A/B，不能据此保证其他机器相同比例的提升。小文档没有测得改善。

另完成100层混合文字、智能对象、调整、填充、形状和组内选择／样式复制粘贴／移动共21项事务；样式与移动各核验一次撤销。实际166服务入口4项连续选层任务成功，任务记录171–203毫秒；客户端往返连同独立COM核对更慢，不能混作任务或按键耗时。颜色／羽化／密度预览确认一次撤销、取消恢复2项回归通过。

共75项真实PS事务：CPU受限59项、正常资源16项；资源均恢复，无新未知结果，用户文档与配置保留。一次混合夹具构造超过心跳有效期，首个捕获前被拒绝、没有执行命令；修正测试流程为等待新心跳后再开新测试，不放宽生产租约。另有381项后台、15份插件脚本（含55组预览模拟）、最终EXE启动／重启和资源匹配检查通过。前端及原生组件无代码修改。

证据：`.runtime/recovery166/runtime.json`、`live-matrix.json`、`.runtime/caps166-candidate.json`及对应测试目录。

## 使用范围与剩余验证

忙碌时仍拒绝新任务，不排队、不自动补按；未知结果仅读取原收据。快速连按间隔短于前一项任务耗时，仍可能被拒绝。此次不宣称“重复几次才执行”已彻底解决；实体Caps键、故障i5／集显／PS24.2及Win10／PS2024仍需对应实机结果。
