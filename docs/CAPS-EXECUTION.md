# 连续组合键与执行耗时

## 174／UXP38：选层读取让行、关闭菜单不重弹

Caps+W／S 仍单选上下图层，Shift组合仍追加多选。基础图层读取与颜色／蒙版读取在小批次之间检查新的交互请求，及时停止未开始的只读步骤，让上下选层执行。基础DOM读取与同步事务校验共用同一实现，保留最新目标、类型、锁定、父组、顺序及最终选择核验；不降低刷新频率、不积压按键、不自动补做被拒绝操作。正在执行的单次PS调用仍须正常返回。

关闭菜单立即隐藏。原确认或取消恢复继续在后台完成，后续进度和完成消息不会重新弹出菜单；可从后台查看任务，或主动再次唤出查看当前状态。任务未结束时仍拒绝新的修改。菜单内沿用173的细进度线，去掉“已固定”和上次操作，不能计量时不显示虚假百分比。

同会话合法、未接受、未执行的修改请求若已过期，UXP38持久返回“执行前已过期，未修改”。已接受／已完成或其他会话的请求不改写，未知结果仍只核对原请求。需要主程序174与实际加载UXP0.3.38配套；保存文档、正常关闭PS，在后台更新内置插件后重新启动确认版本。

## 167／UXP34：小文档与直接 Caps 请求

## 166／UXP33 历史本机验证版

166验证时已切换本机入口，彼时正式 GitHub Release 为165。无需修改原来的 Caps+W／S 或 Shift+Caps+W／S 绑定。

用户反馈需要重复按几次才执行。旧165的实际日志中，两次组合键已被原生钩子识别，并在1–2毫秒内进入后台，但上一项选层任务仍在执行，因此被忙碌保护拒绝。成功任务约172–281毫秒。这证实了一种漏执行原因，不代表所有未响应都只有这个原因。

166先读取待执行请求，再处理可选的菜单／颜色读取；捕获目标后的原有短暂交接窗口也覆盖可选菜单读取，避免下一条写入尚未到达时启动无关读取。不改变后台刷新间隔、快照有效期、Caps按下立即展开或按键判定时间。已开始的宿主读取仍需正常返回，不能抢占。

Caps选择／样式／单步移动事务中，根级列表至少64项时复用已验证的原生标量批量读取，检查操作前后完整图层结构。较小列表沿用DOM；原生接口不支持、返回异常或原生条目超4096时回退完整DOM。全树成员校验使用集合查找。目标身份、完整数量与顺序、最终选择、锁定、写后核验和历史事务保持；深层分组但根级不足64项的文档仍使用原路径。
