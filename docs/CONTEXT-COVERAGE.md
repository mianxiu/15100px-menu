# Photoshop 菜单与输入识别范围

截至v0.4.146（2026-10-16），内置UXP0.3.18。面板位置识别与图层类型识别是两套信息：前者决定菜单入口，后者决定当前图层有哪些可用操作。识别图层类型不代表已识别所有 Photoshop 面板。

| 区域／状态 | 当前处理 | 范围与限制 |
|---|---|---|
| 首页 | 首页菜单、新建与最近预设 | 根据可见的 `OWL.WelcomeScreenView` 判断 |
| 文档画布 | 画布菜单 | 根据 `OWL.Document` 判断 |
| 图层面板 | 图层菜单、排序等操作 | 匹配归一化的中英文填充／锁定／不透明度组合，或已核对的原生控件ID签名；支持已知浮动调色板链，不按控件数量宽泛放行 |
| 标准输入控件 | 阻止图层修改快捷操作 | 焦点为 `Edit`、`RichEdit20W`、`RichEdit50W` 或 `ComboBox`；即使鼠标移到画布也保留输入焦点保护 |
| 属性、历史、工具等其他面板 | 未独立识别时使用通用菜单 | 未实现这些面板各自的语义菜单，不能承诺都能区分 |
| Photoshop 自绘编辑器、文字工具编辑状态 | 尚未全面验证 | 不一定使用标准 Windows 输入控件；需要逐项实机验收，不能宣称全部受输入保护 |
| 模态窗口 | 不属于已验证工作区根窗口时拒绝操作 | 不等于覆盖所有原生菜单或所有对话框形态；不能仅凭缺少标准Edit或caret就认定可执行；完整原生／自绘对话框输入矩阵仍待验收 |
| 其他应用 | Photoshop 前台范围外不触发操作 | 工作区仅接受同 PS 进程中可见、启用且未最小化的已知根窗口 |

“输入框内不执行图层操作”指编辑图层名、文字或数值时，避免把同一按键解释为菜单修改命令。它不是“所有面板都禁止菜单”，也不是“所有编辑状态已经识别”。

菜单打开不在键盘钩子中查询UIA／COM／UXP。图层菜单发独立只读请求，在本次身份确认前不把旧目标置为可执行；基础能力先返回，颜色信息后补，迟到结果受菜单代次／请求ID／会话／目标及草稿保护。后台保留新鲜快照，有效期2秒，慢机器不延长旧目标有效期。单选操作可复用菜单冻结的身份，省去单独读取目标的文件往返；多选及非菜单入口保留原读取。Photoshop修改前在同一操作区内重新校验会话、文档、选中图层、活动图层及可用条件，目标变化拒绝修改。取消菜单不撤销已经提交的任务。忙碌拒绝新任务，超时或断线只核对原结果，不重发。

图层创建位置、默认名称及撤销的历史验收保留；145智能对象转换已由真实PS24.0.1读回。PS25菜单可用已由用户确认，但另一台Win10／PS25.5无UXP菜单条目／心跳是独立未解问题。完整实体按键／焦点矩阵仍未验收：本机键鼠工具无法初始化。后续应针对属性数值、图层名称、文字编辑、历史、图层样式和菜单展开状态分别记录实机结果，不能把自动分类测试当作上述全部状态通过。

实现位置：`backend/panel_context.py`、`backend/photoshop_windows.py`、桌面焦点保护及原生热键组件。

默认Caps意图、上下单选／Shift多选和F5行为见[当前按键](../README.md#photoshop-操作菜单)；画布／通用菜单不显示图层排序，图层菜单上方四段图文，下方c/v/f/w/s。Tab／Caps+Tab仅测试未迁移，自动ENG未启用。面板／触发采集用[inspect-panels](../tools/inspect-panels.ps1)，安装成功未加载用[inspect-uxp](../tools/inspect-uxp.ps1)。

146通过后台统一诊断收集面板／热键、UXP加载及已有运行耗时；UXP日志优先当前运行宿主，早于本次PS启动的记录不用于推断扫描路径。未记录用户External扫描仅为线索，不代表已确认加载失败根因；实体矩阵继续单列待验收。
