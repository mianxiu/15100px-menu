# Photoshop 菜单与输入识别范围

截至 v0.4.118。面板位置识别与图层类型识别是两套信息：前者决定菜单入口，后者决定当前图层有哪些可用操作。识别图层类型不代表已识别所有 Photoshop 面板。

| 区域／状态 | 当前处理 | 范围与限制 |
|---|---|---|
| 首页 | 首页菜单、新建与最近预设 | 根据可见的 `OWL.WelcomeScreenView` 判断 |
| 文档画布 | 画布菜单 | 根据 `OWL.Document` 判断 |
| 图层面板 | 图层菜单、排序等操作 | 需要调色板中同时出现填充、锁定、不透明度控件，支持目前的中英文标签 |
| 标准输入控件 | 阻止图层修改快捷操作 | 焦点为 `Edit`、`RichEdit20W`、`RichEdit50W` 或 `ComboBox`；即使鼠标移到画布也保留输入焦点保护 |
| 属性、历史、工具等其他面板 | 未独立识别时使用通用菜单 | 未实现这些面板各自的语义菜单，不能承诺都能区分 |
| Photoshop 自绘编辑器、文字工具编辑状态 | 尚未全面验证 | 不一定使用标准 Windows 输入控件；需要逐项实机验收，不能宣称全部受输入保护 |
| 模态窗口 | 不属于已验证工作区根窗口时拒绝操作 | 不等于覆盖所有原生菜单或所有对话框形态；当前未根据菜单所有者／插入光标状态统一分类 |
| 其他应用 | Photoshop 前台范围外不触发操作 | 工作区仅接受同 PS 进程中可见、启用且未最小化的已知根窗口 |

“输入框内不执行图层操作”指编辑图层名、文字或数值时，避免把同一按键解释为菜单修改命令。它不是“所有面板都禁止菜单”，也不是“所有编辑状态已经识别”。

菜单打开时读取缓存，不同步遍历所有面板。单选操作可复用菜单冻结的身份，省去单独读取目标的文件往返；多选及非菜单入口保留原读取。Photoshop修改前在同一操作区内重新校验会话、文档、选中图层、活动图层及可用条件，目标变化拒绝修改。取消菜单不撤销已经提交的任务。忙碌拒绝新任务，超时或断线只核对原结果，不重发。

本轮图层创建位置、默认名称及撤销已由真实 PS 执行读回和用户确认。完整实体按键／焦点矩阵仍未验收：本机键鼠工具无法初始化。后续应针对属性数值、图层名称、文字编辑、历史、图层样式和菜单展开状态分别记录实机结果，不能把自动分类测试当作上述全部状态通过。

实现位置：`backend/panel_context.py`、`backend/photoshop_windows.py`、桌面焦点保护及原生热键组件。
