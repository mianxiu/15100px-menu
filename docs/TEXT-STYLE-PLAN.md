# 文字样式读取与一致预览方案

状态：2026-10-28设计与待实施需求，尚未实现；当前正式版仍为0.4.283。目标是读取现有PS文字，在工具内调整的字体、行距及段落样式与最终写入保持一致。先放在文本工具中，后续可独立入口，共用同一读取、草稿和执行链路。

## 当前差距

UXP的`createTextTools.descriptor`已经读取完整`textKey`、`textStyleRange`和`paragraphStyleRange`，并保留在当前目标快照中；`read()`交给面板的只有文字、名称、目标和版本身份。`mappedText`按来源映射原样式，`stylesMatch`在写后校验字符和段落样式，现阶段没有字体／行距编辑协议。

原生`MenuControls::multiline/textPreview`用工具的Body字号和面板宽度排版。283的列表续行对齐也只是本地显示，不代表PS的原文本框宽度、字体、字距、行距、缩进和排版引擎。用相同字体名称绘制，仍不能把本地排版称为PS准确预览。

## 推荐实现

### 读取与草稿

- 在现有文字读取中投影样式信息，不为每次键入重新读取PS或枚举全部字体。原始描述保留在执行端；面板接收有界的可编辑值、样式范围和能力标记。
- 字符范围包括字体的PostScript标识、字号、颜色、自动／固定行距、字距、缩放和基线；段落范围包括对齐、首行／左右缩进、段前／段后及自动行距比例。同时保留点文字／段落文字、文本框、方向、变换、文档DPI和原有排版设置。
- 多字体、多字号或多段落值显示“混合”，不能取第一段的值代表整个图层。调整明确作用于字符选区、当前段落或整层，未修改字段及未知字段保持原值。
- UTF-8编辑选区与PS的UTF-16范围在边界转换。界面单位与宿主描述单位分开；显式换算点／像素与DPI，自动行距和固定行距不能混成一个数值。
- 所有预览和确认引用同一目标快照及草稿版本。改变文字、样式、选区作用范围或目标后，旧预览不得继续确认。

### 准确预览由PS完成

优先实现明确开启的“PS画布预览”，沿用本项目颜色／羽化预览的目标绑定、单事务、取消和未知结果保护；这是待验证的复用方向，不代表现有颜色执行器可直接处理文字。

1. 只读打开与本地内容处理不修改PS。用户明确开启画布预览后，才进入可取消的文字预览事务；保持原有PS前台／输入保护。
2. 由PS对真实目标应用当前文字及样式草稿并排版。输入／中文组合期间不逐键发宿主命令，静置后合并预览值；一次只处理一个预览，过时返回不用，不积压修改任务。具体节奏以旧版低CPU实测决定，不承诺180ms内完成PS排版。
3. 读回并验证当前文字、字符／段落样式、文本框与目标；只有最新草稿得到可信结果，才显示“PS预览已更新”。不以请求已发送或本地动画代替成功。
4. 确认提交已经验证的同一份PS预览状态，不在确认时另算另一套样式。一次撤销恢复原文和样式；取消必须核验恢复。修改或恢复未知时保留保护，不重发、不假定已恢复。

PS画布使用同一宿主引擎与文档排版条件，是本方案确保预览与提交一致的依据。准确面板图片是后续可选项：仅在静默直接像素读取已实测可用时，显示PS生成的图像；图片按比例缩放，不随面板宽度重新排字。不支持时保留可用的画布预览，不开放准确图片按钮，不新建文档、不导出PNG，也不用本地近似排版冒充准确结果。

### 内容处理与样式排版

现有入口先区分“内容处理”和“样式排版”。编辑、查找替换、整理、拆分、列表继续提供快速的本地内容处理；字体、行距、段落缩进进入样式排版。列表最终需要用PS段落属性实现续行对齐，不能只在工具预览里补空格。

UI控件继续遵循共享字体角色和MenuControls；文档文字的字体／行距是被编辑的内容，不改变工具栏和说明文字的UI字号。以后拆出独立面板时，复用同一快照、草稿和事务，不复制另一套样式映射或预览写入逻辑。

## 候选：双击重新编辑的列表对象

这是2026-10-28后续可行性问题，尚未选择或实现，不替代前面的样式读取与准确预览。现有公开UXP接口未提供注册新LayerKind或可取消的智能对象双击前置回调；事件通知不能作为已拦住原生动作的证据。本项目已有Windows原生鼠标hook，可以评估复用，但尚未验证图层缩略图的准确命中及双击接管。

| 承载方式 | 可提供的体验与代价 |
| --- | --- |
| 原生文字层＋列表标记 | 仍是可编辑文字，保存列表层级／编号和样式数据，由插件识别为逻辑“列表对象”；最贴近现有文字读写，优先评估 |
| 嵌入式智能对象＋列表源数据 | 可把多个文字层作为一个可复用对象；插件编辑列表，未运行插件时仍保留普通智能对象和内部文字。读取／更新内部内容、实例共享与跨文档恢复更复杂，需要独立验证 |

拟议交互为：只对已确认的列表对象缩略图双击打开同一个列表／样式编辑器，普通图层、重命名、蒙版、图层样式及其他智能对象保留默认行为。保留Caps／按钮入口作为识别不可靠时的可用路径；不先打开PSB再立刻关掉来伪装无闪烁接管。

实现前必须验证：

- 持久标记和有版本的列表数据随PSD保存，不能仅依赖图层名称、临时layerID或本机缓存；保存重开、改名、复制／跨文档复制、撤销／重做都要保持正确关联。不能未经实测就认定某个元数据字段支持一次撤销；不覆盖其他插件数据，也不执行文档中携带的代码。
- 原生拦截在PS执行默认动作之前完成，且依据真实缩略图区域和新鲜对象身份。hook回调只作有界快速判断，不等待COM／UXP或解析大段数据；身份、命中或输入状态不确定时不拦截。还要覆盖列表滚动、缩略图尺寸、DPI、快速换层和完整按下／松开配对。
- 智能对象方案要验证源数据、内部文字与父文档画面同步，确认／取消及一次撤销完整恢复；共享实例与“通过拷贝新建”不得混淆。原生打开PSB及更新内部内容是否会闪烁也属于门槛，未通过不能声称无切换编辑。
- 插件关闭或没有安装时仍能查看和按PS默认方式编辑对象，不依赖自定义文件关联。PS原生类型／图标不会仅因列表标记而变成新类型；插件自己的识别与筛选需另作明确区分。

依据：[UXP LayerKind枚举](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/modules/constants)、[动作通知接口](https://developer.adobe.com/photoshop/uxp/2022/ps_reference/media/photoshopaction/)。以上是当前公开接口范围的核对与方案判断，不是对全部C++ SDK能力的否定，也不是双击接管的实测结论。

## 分步验收

1. **先读样式**：从现有快照显示字体、字号、行距和段落缩进，包括混合状态；读取不改变PS内容、选择或历史。优先在本机PS24.0.1验证旧版描述路径，不依赖24.1新增DOM接口才能使用。
2. **再写样式**：先闭环单层字体／字号／行距／缩进，保留其余样式及文本框；验证72／300DPI、点／段落文字、自动／固定行距、中英文及混合样式、缺失字体拒绝和一次撤销。之后扩展字符选区、多级列表及更多排版参数。
3. **再开准确预览**：验证旧版低CPU／正常配置中的画布刷新、最新草稿与确认状态一致、取消精确恢复、前台／输入／目标变化及未知结果保护；仅有本地渲染图或接口文档不能算通过。
4. **最后评估面板图片与独立入口**：按实际能力开放，分别记录宿主往返、排版／取图耗时和实体显示延迟。不为图片预览牺牲旧版稳定性，不先承诺跨PS版本像素完全一致。

第一步完成前不宣传已支持读取／调整字体和行距；实际文字预览事务完成前，不把现有纯文字结果称为所见即所得。

## 官方依据与实现边界

- [TextItem](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/textitem)：字符／段落属性及24.1 DOM门槛，部分像素数值与文档DPI有关；旧版复用项目现有描述读写路径，仍需实测。
- [ParagraphStyle](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/paragraphstyle)：段落缩进等属性；实际字段、单位和继承关系以宿主读回为准。
- [模态执行与历史事务](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal)：`suspendHistory/resumeHistory`与提交／回滚；模态结束会自动处理未结束历史，不能跨任意模态调用保存一个悬空事务。
- [Imaging API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)：直接图层／文档取图、目标尺寸、颜色转换与资源释放；取图能力不代表已支持安全的文字草稿预览。
