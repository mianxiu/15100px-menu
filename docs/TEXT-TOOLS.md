# 文本工具

在 Caps 中编辑一个文字图层，预览处理结果，再一次写回或拆成多个可编辑文字层。0.4.264／UXP0.3.71实现；公开下载状态见 [Wiki Versions](https://github.com/mianxiu/15100px-menu/wiki/Versions)。

## 开始前

单选未锁定的文字图层，在 Caps 右侧点击“文本工具”。非文字、多选或无法确认目标时不提供入口。面板从鼠标附近打开，限制在 PS 窗口与屏幕可用区域内；空白处可拖动。后台不再提供重复的文本页面。

## 操作

1. 面板读取所选文字。直接修改“编辑文字”，或选择“查找替换”“整理”“拆分”。266起，编辑区和下方预览都随可用宽度自动折行，长内容可以上下滚动。自动折行只改变显示，不添加换行符；Enter才会插入真实换行，并影响后续按行拆分。
2. 查找替换在修改内容后自动更新匹配预览和输出，匹配文字使用主题强调色；其他页点击“计算预览”。计算和继续编辑不修改 PS，改变文字或选项会立即使旧预览失效。
3. 检查结果，再点击“确认写回文字”或“确认拆分并替换原层”。也可用“将结果继续编辑”，把处理结果作为下一次操作的草稿。
4. 关闭面板取消未提交草稿。“重新读取（覆盖草稿）”会用当前图层内容替换草稿。

| 功能 | 用法 |
| --- | --- |
| 编辑 | 修改文字后计算预览并写回 |
| 普通替换 | 输入查找与替换内容；替换可留空，可选忽略大小写 |
| 正则替换 | 使用 Python 正则；例如查找 \d+ 替换数字，替换中的 \1 或 \g<名称> 引用捕获组 |
| 整理 | 去每行首尾空白、删空行、合并连续空格、指定连接符合并行、转大写／小写 |
| 按行拆分 | 连续分组覆盖所有行，如 1-3,4,5-7 |
| 分隔符／正则拆分 | 不要求原文换行；例如用逗号或 [,，] 分隔，分隔符保留在前一组，纯空白组不单独生成图层 |

## 实时匹配与正则范围

275起，查找替换在停止输入约180毫秒后开始本地计算。上方原文仍可编辑，下面的“匹配”区以主题强调色显示完整匹配，下方结果区同步更新。原文／结果均软换行，零宽匹配计数但没有字符可着色；非法表达式／替换引用或超时显示错误，不能确认旧结果。原计算尚未结束时继续输入，只在完成后计算最新草稿，不并发积压，也不自动写回PS。180毫秒是合并输入的静置时间，不是保证的完整出结果时间。

使用内置Python3.11标准库`re.compile`／`finditer`和`Match.expand`，不是另写的简化正则。Unicode字符串语法由该版本引擎处理，支持数字／命名分组、反向引用、固定宽度后查找、前瞻、条件分组、原子组、占有量词及内联标志，例如`(?m)`、`(?s)`、`(?x)`。替换支持`\1`、`\g<名称>`和`\g<0>`；普通替换不解释反斜杠。输入表达式时直接填写，不加Python的引号或`r`前缀。

这不是Python整个`re`编程接口：不执行替换回调、Python代码或bytes模式；不提供`pos/endpos`、替换次数等API参数。不是第三方`regex`库，不支持它的Unicode属性等扩展，也不自动获得新Python版本新增的语法。PS换行在处理草稿时统一为LF、写回时转为PS段落符；空结果与现有长度／时间保护仍保持。语法以[Python3.11官方说明](https://docs.python.org/3.11/library/re.html)为准。

## 拆分排列

“保留位置”沿用已有换行边界，核验独立文字的字形和位置。“逐行排列”先把分组排成新行，再拆出独立图层；沿用文字的段落设置与变换，不承诺保留拆分前的原画面。

没有换行的文字请选择“逐行排列”。目前不支持把任意词语或字符在原单行中的位置精确拆成独立层；“保留位置”遇到这种边界会拒绝，不会静默改变布局。

## 样式、撤销和限制

确认前重新核验文档、单选图层、原文字和样式。未改动文字按差异映射保留样式，插入／替换内容沿用修改起点样式；整段重排、重复文字的手工编辑可能产生不符合预期的样式归属，建议分步处理并检查结果。颜色、字体、段落、抗锯齿和位置均按对应操作读回核验。拆分保持父组和连续层序。一次确认对应一个历史步骤，可一次撤销；失败尝试回滚，恢复未知时保留原请求，不自动重发。

新处理计划的读取窗口为30分钟，旧字面替换接口仍为60秒。任何实际内容、样式、名称、选择或会话变化仍会拒绝写入；延长编辑时间不减少写前校验。

上限20,000 UTF-16单位、1,024段样式、512KB样式数据、查找／分隔符200单位、替换500单位、拆分64组。空结果、缺失字体、手动字距和不完整样式会拒绝。拆分仍不支持路径／弯曲文字、剪贴、图层效果、多栏、竖排段落和溢出文本。

正则和草稿差异在 PS 外的独立进程计算，超过2秒就停止该计算，不提交 PS。这个期限包含计算进程启动；复杂表达式或复杂长文差异可能被拒绝。Python 正则与 JavaScript 正则语法不同，不能直接保证其他软件中的表达式通用。

## 编辑区软换行的实现

266采用固定的官方ImGui1.92.7-docking，并在共享multiline控件启用WordWrap；旧1.91.9b没有该能力。使用组件自身的行布局、光标和选区，不向编辑缓冲区插入显示用换行。依赖原始来源及SHA在native/vendor/manifest.json，依据[上游说明](https://github.com/ocornut/imgui/issues/3237)。继续预热三档语义字号和有界字形，隐藏时上传字体纹理，避免把必要准备放到首次唤出。

同步处理新版字库初始化／NewFrame就绪阶段、首帧前纹理注册与跨CPU／GPU设备释放、渲染恢复后核心IME／剪贴板回调、旧颜色面板的布局提交，以及新目标不继承旧数值输入状态。字体保持原整数像素取整、原角色和DPI换算；未改PS写入协议。

原生优化构建低CPU矩阵已通过：单行长段落自动折行、缩窄／放宽编辑框、UTF-8光标边界、选区保持、精确复制／粘贴、中文编辑及撤销；显示折行不增加原文换行，真实换行保留。另覆盖字形预热、中文WM_CHAR和IME候选窗位置、渲染恢复、颜色／蒙版混合值、焦点和取消；不是实体键盘或PS实屏验收。完整回归、实际入口和PS验收按TODO记录，不提前标为通过。

初次启动／平台回调／布局错误、撤销夹具与独立无窗口模型、旧密度输入串入新快照及首帧前跨设备纹理错误的诊断均保存在.runtime/*266*；没有关闭断言或移除保护。650项低CPU回归、软件渲染启动／响应／正常关闭、优化原生完整矩阵、三档字号当前主题预览、冻结启动／重启均通过。依赖文件逐一匹配官方源及固定SHA；上游三处既有行尾空格原样保留。实际266／UXP71入口、dist、运行菜单／热键与冻结资源一致，未重启PS。

PS24.0.1低CPU／正常各6项文本操作及两组查找通过，原稿、配置、会话、历史未知和资源保持；12次任务及面板关闭后IME重新禁用。正常组第3项在打开面板前被焦点保护拒绝，未提交修改；保留foreground-refusal-report.json，在新隔离文档完成剩余4项，无未知请求重发。证据为.runtime/text266-live/report.json、search266-live.json和runtime266-verified.json。实体键盘／PS实屏、其他DPI／硬件仍待验，没有性能提升声明。
