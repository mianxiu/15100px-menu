# UI 指南

## 文本工具自动预览

查找、替换、大小写或草稿变化后，静置180ms自动请求本地计算；只保留当前草稿世代，旧返回不显示、不允许写回。计算进行中可以继续输入，待原计算结束后再计算最新草稿，不并发积压。空查找不提交，非法表达式／超时显示错误，只有当前有效计划可确认。自动计算不调用PS，不自动写入；277起编辑、整理、拆分和列表也沿用此机制，移除手动计算按钮；拆分条件为空时不请求，非法分组显示错误，修改后才重新计算。列表使用同一分段控件、Control按钮／Body编辑与预览／Secondary说明角色。

原文可编辑区保留原有输入／选区／撤销；新增只读匹配预览使用共享textPreview、Body字号和主题CheckMark强调色，按同一Python匹配结果的UTF-8边界着色完整匹配，不逐帧运行第二套正则。零宽匹配计数但无字符着色；输出区自动显示替换结果。折行只影响显示，不插入真实换行，不注册额外命中或改变菜单锚点。

## 274静默预览能力门槛

预览只使用宿主现有getPixels直接读取；取消新建文档和PNG导出回退。原生结果行仅在直接像素接口可用且目标不是组／单独调整层时显示预览图标；不支持时移除真实控件和命中区域，行主体仍可定位。旧layer_thumbnail_available心跳不能启用旧路径，后台与UXP也拒绝新的layer.thumbnail。错误／超时／失鲜不触发副本或导出，不改既有输入、焦点、会话及未知保护。

## 269转换色彩模式、标签和预览兼容

纯色／渐变的共享颜色读取兼容RGBColor中的redFloat／greenFloat／blueFloat。CMYK转RGB而不合并时，RGB／8位填充仍可能保留这种带色域外值的描述；仅将菜单显示值换算到0–255，未改变颜色时保留原始描述，明确改色才写入RGB。不得因显示换算直接规范化原稿。PS24.0.1隔离复现中，原始值为(-0.20132526755333,0.61908257007599,0.85920709371567)，原生取样为(0,157.996108949416,219)，原入口不可用证据保留在.runtime/fill269-float-calibration.json。

270补充色彩模式核验：实际270／UXP75没有修改颜色代码；269的共用浮点RGB读取已覆盖RGB对照，以及CMYK／Lab／灰度转RGB后保留的纯色层。PS24.0.1低CPU／正常、8／16位共16组通过原生取样与菜单RGB（8位显示精度）、读取不增历史、不改色保留原始描述、改色后一次撤销及组结构保持；原稿／配置／CPU资源恢复。源CMYK配置为U.S. Web Coated (SWOP) v2，灰度为Dot Gain 20%，Lab为固有D50，目标为sRGB；其他自定义ICC、32位／HDR及实体面板点击不算通过。

仍保持CMYK／Lab／灰度模式的文档被现有RGB8／16门槛明确拒绝，这不是转换后读取问题。本轮未解除此限制；原模式直接编辑需要另行处理ICC与色域往返验证，不能直接使用仅按应用工作空间转换的core.convertColor冒充文档配置文件保色。位图／索引／多通道等也不能承诺可保留同样的填充层编辑能力。证据.runtime/colors270-mode-coverage-verified.json、colors271-converted-baseline.json、colors271-converted-rest.json与对应脚本；首轮颜色取样器改变夹具历史、Lab无ColorProfileName导致的夹具失败保留，修正后独立12项补测与先前4项逐条核验。运行版本仍为270，没有另建二进制或发布新版本。

新增标签的最低版本细分为PS25.2；原生可见项、UXP执行与JSX执行同步限制。Adobe社区专家明确报告25.2已提供11种颜色，但本机没有PS25实机，不能把此边界判断或模拟枚举测试当作新增四色实测。宿主色表接受有效小数通道并统一舍入；启动失败最多三次间隔重读，同一进程的多个PS主窗口不再误判为多个宿主。每项标注真实色表／备用来源，缺项不冒充宿主匹配。

Adobe明确getPixels不支持图层组。组直接走隔离副本；其他目标仅在匹配读取已返回明确不支持时回退。读取超时、目标失鲜、优先任务打断不触发回退。直接接口按长边请求128像素，校验格式并释放imageData；源检查与操作锁保持。临时副本先与自建空白像素层合成再读边界，兼容只有纯色的组；不向原组插层、不修补PS原生PNG导出。RGB／8位、文档面积／组层数、未知保护和缓存限制保持。

## 新功能必须复用的 UI 契约

本节是当前实现入口；下方带版本号的内容是历史记录。位置／交互按最新用户决定，不能从旧记录恢复已废弃布局。

- 文字层级先遵循[文字审计与强制规范](UI-TYPOGRAPHY.md)。原生唯一字号入口为 `MenuTypography.h` 的Body／Control／Secondary及已验收的预设专用角色；禁止功能视图直接选字体缓存或局部缩放。后台只使用admin.css的语义字号／行高／字重变量，窄窗口不另外缩字号。
- 新增原生面板使用 `native/*Panel.h`，在绘制范围内使用 `MenuControls::PanelStyle(scale)` 自动取得Control字体；内容按Body／Secondary切换。按钮、输入和筛选分段使用 `MenuControls::button/input/segments`。不在面板里直接拼默认 ImGui Button／Selectable／InputText，不另设字体、圆角、描边或颜色值。此规则替代旧固定menuFonts[0]的要求。
- Caps 与工具面板共同使用 `MenuControls::surface/outline/segment`。度量唯一入口是 `MenuUiMetrics.h`／Figma 指标，颜色来自当前 PS 主题，阴影唯一入口是 `MenuShadow.h`。当前控件高24、文字内边距9、面板及常规间距6、边框1、圆角4逻辑单位，均按 DPI 缩放。
- 同一排筛选项用共享圆角外框和内部直线分隔；空间不足按整段换行，不恢复下拉。输入／按钮同高，键盘导航、真实命中、分隔线取消、禁用和焦点保护同步验证；视觉状态不能扩大执行范围。
- 新控件先补到共享组件，再供功能调用；确需新视觉规则时，更新组件、此契约和测试，一起核验 Caps 与工具面板。不要在具体功能文件追加覆盖补丁。旧颜色编辑等专用几何按改动需要迁移，不借统一样式移动已验收锚点。
- `tools/build-menu-host.ps1`及PyInstaller冻结前运行 `tests/test_menu_ui_contract.py`；前端npm build前运行typography契约；GitHub push／PR运行UI contract。违规阻断构建，覆盖未来新增原生及前端视图。原生自测核验三档字号的层级、共用字体、输入／按钮尺寸、样式恢复、筛选点击、分隔线及禁用。静态契约不能代替视觉检查，当前主题同时查看Caps、查找、有结果／空／运行／错误、拆分及颜色输入，改配色时补充受影响明暗主题。
- 新面板／组件交付必须包含实际入口版本及组件一致性；保留鼠标附近定位、PS边界、F／Shift+F、输入／焦点、忙碌、取消和失鲜结果保护。模拟、自测、离屏预览和真实 PS 实屏分别记录。
