# 153：按文档大小读取创建树

Photoshop Menu v0.4.153／UXP0.3.23已构建并切换本机运行入口；真实PS24.0.1测试通过。更新EXE后还需正常重启PS，确认后台实际加载插件0.3.23，才会使用新算法。正式下载见[Latest](https://github.com/mianxiu/15100px-menu/releases/latest)。

## 使用与算法范围

无需开关。空白图层、纯色填充、打组、曲线／色相饱和度／色彩平衡／黑白创建事务，前32个节点仍使用原来的DOM读取；整树不超过32节点时完全不发起新增原生树查询。读到第33个节点时，改用文档计数加一次有界multiGet，批量读取ID、父组、组边界及原生顺序，在内存构造完整前序树。阈值按完整树节点计算，不按PSD文件体积或画布像素；嵌套在少数根组内的大文档也能触发。

校验连续且完整的原生索引、唯一ID、父组与组边界闭合，并与已读DOM前缀逐项核对；支持含背景层。原生计数超过4096、接口不支持、查询失败、结果不完整或矛盾时，回到原DOM整树读取。原生范围含组结束记录，实际可加速节点数因组数量而异；超范围保留准确性，不承诺提速。

本次仅替换创建前首次整树扫描。写后保留新鲜DOM结构遍历，并在同一事务中复用已确认的“是否组”标量；新节点仍重新读取。选中目标、父组同级顺序、原生插入位置、原层保留、新层数量／类型、打组成员均继续核验，颜色、样式、路径和蒙版不进入该批量读取。异步读后再次核对文档与精确选择、取消和到期，才允许写入。

无跨请求整树缓存，不延长状态有效期，不修改菜单轮询／刷新或Caps展开时机。保留一次撤销、失败回滚、忙碌拒绝、完成前新选择准备，以及未知结果只核对原请求、不重发或切COM的保护。标签、排序、智能对象和调色并非本次整树算法替换范围，既有功能另做回归。

## 验证与限制

本机实际PS24.0.1：24类288命令，100节点四类28命令，1000节点7命令，4096×4096三类36命令，共359项成功命令（含原本已是智能对象的已核验无修改），32项旧目标拒绝；逐项独立描述符／路径／蒙版／样式／父组／顺序读回与一次撤销。另19项形状颜色／羽化／密度、40项原生创建命名／位置对照、15项单选／Shift追加、25项自然刷新、8项完成后新选择反馈、最终冻结服务10次含背景百层文档创建及真实标签命令通过。完整创建基准旧／新各250次含预热，共500次，计入各200次。330后台、33前端、12份UXP脚本与实际组件原生自测、最终EXE隔离启动／重启通过。 另通过冻结服务连续10次跨越32节点阈值，以及3类真实PS旧／新独立DOM验证器的完整ID／名称／父组／顺序、描述符与历史不变对照。 最终修正版的冻结EXE创建合计50次（包括上述百层与阈值场景），覆盖百层含背景、选中背景、两级嵌套含背景、透明文档与阈值跨越；保留首轮背景走DOM回退的失败记录。修正只影响背景索引校验，无背景判断表达式等价，修正前对应无背景实机数据单独标明复用。

新路径模拟覆盖4／31／32节点仍走DOM，大树／嵌套／背景批量，缺行／重复／错误父组／索引／组边界／前缀、不支持和超范围回退，批量读取后旧目标／取消拒绝，以及新建读回失败整笔回滚。实际EXE与dist、内置／安装／宿主加载UXP版本及原生组件分别核对；冻结服务生产WebSocket连续10次大文档创建、独立顺序读回和撤销通过。

实体Caps／鼠标整套验收、故障i5集显／PS24.2、Win10／PS2024及更高宿主仍未完成；本机事务、原生自测与模拟异常不能代替这些实机结果。不存在已经覆盖所有电脑的“最终优化”结论。
