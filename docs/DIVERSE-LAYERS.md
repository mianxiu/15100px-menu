# 152：多类型图层与读取策略实测

2026-10-17，本机 Photoshop 24.0.1，实际程序 v0.4.152／已加载 UXP0.3.22。本轮是生产功能的扩展实测与候选算法研究，没有把实验读取器替换进生产执行路径。不能将本机结果称为最终优化或全配置验收。

## 真实 Photoshop 操作矩阵

24 类样本每类 12 项命令，共 288 项；再对全部类型追加 24 项转换审计，对 4096×4096px 的三类样本追加 36 项命令。合计 **348 项成功命令、51 项旧目标拒绝**，另通过 19 项形状颜色／矢量蒙版回归。重复调试样本、原生命令参考与夹具创建不计入这些数量。

| 类别 | 样本 |
| --- | --- |
| 像素 | 有像素、空白、投影＋外描边、像素蒙版 |
| 文字 | 普通文字、投影＋外描边文字 |
| 智能对象 | 嵌入对象、投影＋外描边、像素蒙版、真实高斯智能滤镜 |
| 矢量／填充 | 矩形形状、带样式形状、纯色、渐变、图案填充 |
| 调整层 | 曲线、色阶、色相饱和度、色彩平衡、黑白 |
| 结构／外观 | 剪贴、隐藏、37%不透明度＋正片叠底、两级嵌套组内目标 |

主矩阵命令为标签红色／清除标签、置顶／置底、转换智能对象，以及空白、纯色、打组、曲线、色相饱和度、色彩平衡、黑白创建。每项独立冻结目标，成功后恢复该项之前的原生历史状态，再进行下一项；不是同时提交或排队。转换审计另独立读取原生 `layerKind=5`、父组和其他原层顺序。

小画布为显式 181×181px、RGB8；大画布为4096×4096px，覆盖带样式像素、带样式智能对象、智能滤镜对象。图层内容、样式和数量是固定夹具，不代表任意复杂 PSD；大画布测试也不能替代集显故障机。

## 如何判断正确

通过 COM 建立可丢弃样本、独立读取 Photoshop 原生描述符与图层树；命令由实际安装的生产 UXP 执行，通过源码生产桥提交。检查文字、智能对象描述、变换、样式、填充／矢量路径、蒙版、可见性、不透明度、混合及剪贴字段；一般操作期间与撤销后分别比较。转换会改变对象表达，检查新类型／父组／其他层不变，并在一次撤销后比较原始描述符。新建核验类型、数量、原生位置与 `placement_moves=0`。反馈选择、后台新鲜类型／能力与旧目标拒绝同时检查。

已经是单个智能对象时转换保持不变，不新增历史；因此348项包含合法无修改命令，不全部算作写入。其他受测修改恢复一次历史即可还原。撤销采用 Photoshop 原生选择恢复规则。

两项原生对照避免了错误结论：

- 智能对象的 `smartObjectMore.placed` UUID 在 Photoshop 原生改标签时也会重建。仅在比较中移除这一字段，其余扩展描述、变换、样式、蒙版仍逐字节比较；没有忽略整个智能对象描述。
- 剪贴成员离开基底排序或被单独打组时，原生置顶／置底／打组也会解除该样本的剪贴关系。这三项比较完整原生参考结果，其他操作仍与原值比较；撤销必须恢复剪贴。没有全局忽略剪贴字段。

首轮测试器曾把智能对象无修改终态当作必须新增历史，另曾把剪贴原生变化当作损坏；原生对照修正验收规则后，分别补测独立终态与完整描述。图案夹具曾因四字符类型解码及变量作用域初始化失败，在生产命令发布前停止；隔离作用域并用已验证的原生构造器对照后通过。没有重发未知修改或清除未决保护。

## 算法结论与限制

同机交替比较每场景12对测量，另有预热。首轮普通只读原型34场景（包括实际1000层混合及背景）完整结构一致；随后按生产首次遍历的Array.from、常量与快照内kind缓存重建基线，分别测5个相同executeAsModal执行域、3个普通只读场景。合计504对／1008次被计入的树读取全部ID、父组、顺序和组边界一致；同域与修正基线的全部样本额外核对历史不变。

| 相同modal中的整树读取 | DOM 中位／P95 ms | 批量标量 中位／P95 ms |
| --- | --- | --- |
| 4层像素 | 1.5 / 3 | 1.0 / 3 |
| 100层混合 | 29.0 / 48 | 4.0 / 20 |
| 300层混合 | 83.0 / 112 | 11.0 / 29 |
| 两级嵌套／实际304节点 | 106.5 / 145 | 11.5 / 16 |
| 100层含背景 | 31.0 / 34 | 4.0 / 5 |

以上只计函数内首次整树读取，排除modal获取、请求文件、PS写入、结果持久化、后续核验和屏幕显示；不是完整命令或菜单唤出延时。生产写后遍历会复用本事务kind缓存，本表没有测量那一阶段。毫秒时钟与每场景12个样本不足以解释小文档亚毫秒差异或保证长期P95。

执行域的差异很大：修正生产遍历基线后，普通只读100／300层混合DOM中位581.5／1750.0ms（精确值见原始报告），不能将它与同modal的29／83ms混比。4层普通只读批量查询P95为61ms、DOM36ms，因此不支持把所有入口一刀切。首轮1000层混合普通只读原型DOM5799.5ms／批量52ms是该原型／执行域的探索结果，不代表当前生产操作能快百倍。

最值得继续验证的是大文档创建前的整树扫描：少量批量宿主查询后在内存组织图层树；小文档保留原路径，写后核验另测。当前仍保留生产152／UXP22，不启用候选。完整连续事务A/B、失败回滚、未知结果恢复、原生接口异常回退、长期尾延时及跨配置尚未完成。

1000层复杂混合样本原生构造一度让PS不响应，随后正常恢复、读取完成；构造不计入读取速度。开发基准已增加循环间协作式构造预算（默认120秒），超限在自建夹具中正常报错，单个已运行原生步骤仍等待返回，不强制结束PS。这不是生产执行超时、缓存有效期或忙碌保护的修改。

候选方法先读取条目数和背景状态，再批量读取 `layerID / parentLayerID / layerSection / itemIndex`，在内存中组织树；两种方法都必须完整覆盖 ID、父组、顺序及组边界。遍历／解析仍是 O(n)，主要减少逐层跨宿主调用，并非将整树正确性核验变成 O(1)。它不读取像素、名称、样式或 get-all，也不能代替活动目标类型、锁定与最终读回。

普通只读入口与生产的 `executeAsModal` 执行域成本不同，不能将前者的巨大比例换算成实际命令提速。本轮没有成对替换完整创建／排序事务、回滚和结果恢复链，所以不启用实验算法，不发布新 EXE。下一步门槛是相同 modal、相同完整连续事务的成对测量，保留新鲜身份、原层／数量／父组／顺序／位置／类型核验、单次撤销、失败回滚与未知结果不重发。小样本尾延时波动也需要扩大采样。

未覆盖实体 Caps／鼠标、故障 i5／PS24.2、Win10／PS2024、链接对象与外部资源丢失、视频／3D、复杂画板、完整模式／位深组合及持续数小时压力。不能据此承诺所有配置同样速度或永不失败。

## 复现与证据

运行当前后台并加载对应内置 UXP 后，用 `tools/verify-diverse-layers.py --output <本机报告.json>` 测主矩阵；`--actions convertSmartObject` 测独立转换，`--kinds pixel-effects,smart-effects,smart-filter --size 4096` 测大画布。工具仅操作自建临时文档、恢复原活动文档；有未决结果则保留样本并停止进一步 PS 控制。不要与其他变异测试或人工编辑并发运行。

树实验来源为 `tools/fixtures/tree-snapshot-study` 与 `tools/benchmark-tree-snapshots.py`，需先在正常关闭 PS 后临时注册独立探针，完成后正常关闭移除自身登记及文件，再恢复生产插件和原文档。它不属于发行包，不能通过改生产插件来启用。`--modal` 为同执行域只读比较，不创建历史；`--cases` 选择固定样本。不能把普通只读与 modal 的数字混在一起。

本机证据：`.runtime/diverse152-summary.json`（去重索引）、`diverse152-matrix.json` 中18个完整类型、`diverse152-remaining.json` 中4个完整类型、`diverse152-extra.json` 中2个完整类型、`diverse152-convert-audit.json`、`diverse152-4k.json`、`shape152-diverse-regression.json`、`smart-native-control.json`、`clipped-native-control.json`。部分报告在后续夹具失败时中止；只统计其中已独立完成、持久化且撤销还原的类型，失败类型的重测另有完整报告。原始报告与文档／配置路径保留本机，不随公开仓库发布。

树读取证据：`.runtime/tree152-comparison.json`（首轮原型）、`tree152-modal.json`（相同执行域）、`tree152-cached-readonly.json`（修正基线）。临时探针正常移除与实际运行核验记录另见`diverse152-runtime-final.json`。
