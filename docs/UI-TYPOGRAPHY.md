# 文字层级与强制规则

适用版本：0.4.255起。本文与UI-GUIDE.md的当前契约共同约束后续UI；旧版本记录中的局部字号不再作为实现依据。

## 254盘点与原因

盘点覆盖Caps基本操作、排序／移动、智能对象、底部字母栏、悬停tip／底部信息、预设卡片、F查找、文字拆分、颜色／羽化输入、独立收尾／诊断提示及后台管理。

| 范围 | 254实际路径 | 问题 |
| --- | --- | --- |
| Caps基本操作、移动、拆分入口、颜色展开 | PS小／中／大正文×95% | 已有明确操作字号，但与其他操作不同路 |
| 智能对象、文档顶／底、字母栏 | 固定menuFonts[0] | PS大字号时明显比相邻按钮小 |
| 查找／拆分、颜色数值 | 固定menuFonts[0] | 面板没有跟随PS字号，复用控件不等于复用文字角色 |
| tip、底部文档／状态 | 固定menuFonts[0] | 辅助说明没有稳定地跟随正文，大小关系随PS设置改变 |
| 独立收尾提示／诊断倒计时 | 前者11／12／13，后者固定13 | 同类状态提示层级不同 |
| 预设尺寸／单位／标签 | 三档尺寸＋独立8.5单位／标签 | 用户已确认的专用层级，应作为明确例外保留 |
| 后台管理 | body变量之外仍有10～18px局部值、浏览器small默认和窄窗口覆盖 | 相同正文／说明在不同页面或宽度下变化，行高也不同 |

根因是缺少语义字体入口：现有检查约束颜色、留白和控件，却允许直接选字体缓存、局部缩放及CSS字面量。UI-GUIDE原契约甚至指定面板固定用menuFonts[0]，与跟随PS字号的主按钮冲突。255同时修改实现、文档与构建检查，不把规则仅写在说明里。

## 原生文字角色

唯一入口为native/MenuTypography.h。B表示PS设置对应的设计em：小11、中12、大13；字体加载会转换字体自身度量并且只乘一次当前屏幕DPI。因此表中数值不是截图中文字包围盒高度，也不与浏览器CSS px直接比较。

| 角色 | 小／中／大设计em | 使用位置 |
| --- | --- | --- |
| Body | 11／12／13 | 中心说明、搜索结果图层名、拆分原文与预览 |
| Control | 10.45／11.4／12.35（B×95%） | 全部操作按钮、字母栏、输入、筛选、颜色／羽化数值和展开说明 |
| Secondary | 10／11／12（B−1） | tip、文档／任务信息、搜索结果文档名／类型、分组帮助、独立收尾／诊断提示 |
| PresetDimension | 10／10.75／11.5 | 已验收的预设尺寸数字 |
| PresetTag／PresetUnit | 8.5 | 已验收的预设小标签及尺寸后缀，唯一固定字号例外 |

同一角色必须用同一字体对象完成测量和绘制；不能用大字体测宽、以小字体绘制，或只改可见文字而留下旧命中。ImGui字体缓存会取整到物理像素，低DPI时Control与Secondary可能落在同一像素字号，测试按该量化检查，不为强行差一像素加入额外缩放。辅助信息沿用对应区域的主题文字色。操作仍高24、内边距9、常规间距6、圆角4逻辑单位；文字宽度变化时按钮及命中共同按实际宽度计算。菜单锚点、两排图标、预设卡片和取消规则保持。

MenuControls::PanelStyle自动使用Control，不再允许调用方传入固定字体。内容切换使用MenuTextStyle(Body／Secondary)，原生手绘文字使用menuFont(role)。字体角色预热并复用，PS字号变化选已有缓存；不在键盘钩子或每帧加载字体，不增加宿主查询。

独立Win32提示沿用原GDI绘制与非激活／穿透保护，字号取同一Secondary设计em；它不具备与ImGui完全相同的字形栅格化，不把它描述成像素级一致。

## 后台文字角色

后台保留浏览器阅读密度，不把原生紧凑菜单的em机械换成CSS像素。统一角色在frontend/src/admin.css的:root定义；浏览器缩放仍可用。

| 角色 | 字号／行高（CSS px） | 使用位置 |
| --- | --- | --- |
| Title | 18／24 | 页面标题 |
| Section | 14／20 | 区块标题 |
| Emphasis | 16／24 | 主要文档／插件名称及重要结果 |
| Body／Control | 13／20 | 正文、按钮、输入、导航、任务名称 |
| Secondary | 12／18 | 帮助、说明、版本、状态标签、时间、表格 |
| Symbol | 18／20 | 关闭／展开符号，不作为正文角色 |

字重只用normal400／medium500／strong600三个共享变量。small明确采用Secondary，不使用浏览器默认缩放。窄窗口只调整布局／间距／必要内容显示，不改变同一角色字号。帮助段落继承说明角色，日志保留等宽字体与20行高这一阅读例外。

## 未来必须实施

1. 新文字先选已有角色，再复用共享组件；不为单个页面另设字号、行高或字重。不直接索引menuFonts、不局部乘FontSize、不用SetWindowFontScale缩放文字；不在CSS／JSX中写裸字号或内联fontSize。
2. 确需新角色，必须同时更新中央定义、本文、UI-GUIDE与契约测试，说明角色与已有角色的区别；不能在功能面板内豁免。
3. 原生构建、前端npm build和PyInstaller冻结打包均有阻断检查。GitHub的UI contract工作流在push／PR运行相同契约，覆盖未来新增原生视图及前端源码。工作流不是分支保护；仓库管理员仍可绕过本地流程或检查，未修改仓库权限设置。
4. 自动检查不能替代视觉验收。每次文字改动至少检查当前主题下的小／中／大字号：Caps、查找有结果／空／错误、拆分、颜色数值、tip与底部信息；覆盖长中文、换行／裁切、真实命中、分隔线、输入／焦点及取消。保留预设尺寸领先标签。
