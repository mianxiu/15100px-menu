# 预览进度与恢复提示

169／UXP36 为颜色、羽化和密度实时预览增加分阶段反馈。需要同时更新主程序与内置插件，并正常重启 PS 加载新版插件。

## 如何查看

拖动编辑面板时，下方信息区显示读取、写入、核验、画布刷新及当前预览已更新。旧版独立执行端能报告逐层完成数，例如“核验图层 · 12/32”；进度条在实际计数之间平滑追赶，不会提前超过已完成量。每一阶段与每一轮最新调整分别计数，不把一次阶段完成当成整个事务完成。

现代 PS 的原生批量调用没有逐层回调，执行期间显示往返动画，原调用返回并核验后才报告完成量。不会为了显示百分比拆分原生批量操作。画布刷新、准备与历史恢复同样使用往返动画；阶段长时间没有返回会显示“等待 Photoshop”，动画持续运行，不代表 PS 已取得新进展。

## 确认与取消

面板内松 Caps 或固定菜单后再次 Caps 确认：编辑面板收起，保留中心运行圆环及确认进度，原请求核验结束后收起。Esc、右键、中心／空白松键取消：先显示“已请求取消 · 等待当前步骤返回”，PS 接受取消后显示恢复原值、刷新恢复画布、核验恢复结果。不会在原生刷新仍未返回时声称已取消。

恢复提示不阻塞其他应用。再次关闭可收起提示；切到其他应用立即收起，不自动抢焦点或重新弹出。提示收起不意味着任务已结束；在原请求终态确认前仍阻止其他修改，未知结果不重发。保留最新值合并、实时预览、取消恢复和确认后一次撤销；进度只是反馈，不参与执行、目标校验或判断成功。

## 开销与适用范围

进度通过当前请求的本机文件传递，只读取已在执行中的计数，不额外读取 PS 图层或轮询 COM。逐层反馈在同阶段约100毫秒内合并，后台读取与界面绘制独立于 PS 执行。不会通过降低准确性或放慢预览刷新来换取动画。

进度反馈改善等待感受，不承诺缩短 PS 本身的运行时间。旧PS双逻辑处理器下的大批量预览仍可能需要数秒至数十秒。实际 i5／集显／低内存及不同PS版本必须分别验证，CPU限制不等同那些硬件。

## 本轮验证

本机 PS24.0.1／169／UXP36：12项真实预览事务（10项双逻辑处理器／Below Normal、2项正常）通过，覆盖2／8／32／128层、部分属性、跨组、确认一次撤销、取消恢复、填充／描边和独立像素蒙版；另4项目标保护检查通过。所有新请求有终态，CPU资源、用户文档与配置已恢复，旧未知／失败记录保留。

398项后台／原生回归、16份插件JS套件（批量30组）、12份四主题阶段渲染、最终EXE启动／重启及实际组件一致性通过。生产 SetWindowPos 显示路径验证了松键后的恢复提示可见、关闭后进度不重新弹出。渲染及模拟消息测试不是实体键鼠／画布视觉验收。

本轮单次样本：双逻辑处理器2层首帧约1.64秒；8层取消测试首帧约2.38秒；32层首帧约6.95秒；128层首帧约30.08秒、第二帧同时改两项约23.30秒。128层读回255份不同进度快照，覆盖读取、写入、核验、刷新和取消恢复；没有新增未知结果或超时资源残留。这些是宿主事务计时，不是鼠标到屏幕延迟，也不是同会话性能A/B，不能据此宣称加速。

现代PS分支通过模拟，尚未有本轮现代PS实机验收；实际故障i5／集显／Win10与实体Caps／鼠标流畅度仍待对应电脑验证。
